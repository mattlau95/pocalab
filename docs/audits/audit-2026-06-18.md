# UX Audit Report — pocalab

> **Date:** 2026-06-18 · **Reviewed:** `http://localhost:3099` (home / first-run state) · **Tools run:** Lighthouse 13.4.0, pa11y 9.1.1, manual code review

---

## Executive summary

pocalab is a well-built, client-side print layout generator with solid fundamentals: excellent performance, strong unsaved-changes protection, thorough `prefers-reduced-motion` support, and semantic HTML throughout. The single blocker is a WCAG 2.2 AA color-contrast violation on the upload zone's "click to browse" link — everything else is polish and accessibility hardening. **1 blocker, 7 important, 3 polish.**

**Snapshot**

- Checklist items passing: **~42 / 52**
- Core Web Vitals: LCP **0.8s** · INP/TBT **0ms** · CLS **0** *(2026 thresholds: <2.5s / <200ms / <0.1 — all pass)*
- Lighthouse: Performance **100** · Accessibility **100** · Best Practices **100**
- pa11y: **1** WCAG 2.2 AA violation

## 🟡 P1 — Important

| # | Finding | Checklist ref | Evidence | Fix | Effort |
|---|---------|---------------|----------|-----|--------|
| 1 | Multiple icon-only buttons have no accessible name — screen readers announce them as "button" | §7 — accessibility | Code review: eye dropper button (`CropEditor.tsx:329`), rotate ±, zoom ± (`CropEditor.tsx:274,288,296,308`), grid toggle (`CropEditor.tsx:378`), edit/replace buttons in `DeckCard.tsx:83–86,88` — these have `title` only, which is not a reliable accessible name | Add `aria-label` to each; e.g. `aria-label="Pick color from image"`, `aria-label="Rotate left"`, `aria-label="Zoom in"` | ⚡ |
| 2 | Copy count ± controls have no label — screen readers cannot identify what they increment | §4 — forms / §7 — accessibility | `DeckCard.tsx:134–152` — the "−" and "+" buttons and the number display have no visible label or `aria-label` explaining "copies" | Wrap in a `<fieldset>` with `<legend>Copies</legend>` or add `aria-label="Decrease copies"` / `aria-label="Increase copies"` and `aria-live="polite"` on the count | ⚡ |
| 3 | Fade/opacity slider is not programmatically linked to a label | §4 — forms | `CropEditor.tsx:357` — `<input type="range">` has an `id` but no matching `<label htmlFor>` | Add a `<label htmlFor="crop-fade">Background fade</label>` before the slider | ⚡ |
| 4 | No skip link — keyboard users must Tab through the entire header on every page load | §7 — accessibility | Not present in `index.html` or `App.tsx`; WCAG 2.4.1 bypass blocks criterion | Add `<a href="#main-content" class="skip-link">Skip to main content</a>` as the first child of `<body>`, and `id="main-content"` on `<main>` | ⚡ |
| 5 | `localStorage` write failures are swallowed silently — project won't persist and user won't know | §6 — don't lose work | `src/hooks/useProject.ts:163,180` — `catch` blocks do nothing; if storage is full the project silently fails to save | Show a one-time toast: "Couldn't save — storage may be full" and surface it via the existing toast system | ⚡ |
| 6 | EyeDropper API failure is silent — no feedback if the browser doesn't support it or the user cancels | §3 — errors / edge states | `CropEditor.tsx:184` — `handleEyeDropper()` has no catch/user message | Wrap in try/catch; show a small error message or disable the button when `'EyeDropper' in window` is false | ⚡ |
| 7 | Export error gives no retry affordance — users must find and re-click the export button themselves | §3 — errors | `App.tsx:652,658` — error text appears but no "Try again" button is rendered alongside it | Add a `<button>` styled as a link next to the error: `onClick={() => { setExportError(null); handleExport(); }}` | ⚡ |

| # | Finding | Checklist ref | Evidence | Fix | Effort |

2. **[P1 ⚡]** aria-labels on all icon-only buttons (eye dropper, rotate, zoom, grid toggle, edit, replace) — quick find-and-add pass over `CropEditor.tsx` and `DeckCard.tsx`.

4. **[P1 ⚡]** Skip link — one-liner in `index.html` + `id="main-content"` on `<main>`.
5. **[P1 ⚡]** Fade slider label — add the missing `<label htmlFor>`.
6. **[P1 ⚡]** localStorage failure toast — surface the silent catch in `useProject.ts`.
7. **[P1 ⚡]** EyeDropper error handling — disable button when API unavailable; catch cancel.
8. **[P1 ⚡]** Export retry button — inline "Try again" next to the error message.
9. **[P2 ⚡]** `aria-busy` on export area.
10. **[P2 ⚡]** Autosave indicator (debounced "Saved" badge).
11. **[P2 🔨]** Replace `window.confirm()` calls with styled custom dialogs.

## What passed

- **Core Web Vitals**: Flawless — LCP 0.8s, TBT 0ms, CLS 0. The app is lightning fast.
- **`prefers-reduced-motion`**: Thorough — global CSS reduction + per-component checks, including the `matchMedia` call in card removal animation timing.
- **Unsaved changes protection**: `useBeforeUnload` hook correctly guards navigation when work is in progress.
- **Autosave**: Every project change persists to localStorage; session recovery on reload with format migration.
- **Semantic HTML**: `<header>`, `<main>`, `<button>`, `<label>`, `<details>`/`<summary>` — no div-soup.
- **Toast/live regions**: Card-added and PDF export toasts use `role="status" aria-live="polite"` correctly.
- **Two-step card removal**: Dedicated confirm/cancel button pair with `aria-label` on each — avoids `window.confirm()` for the most common destructive action.
- **Crop editor keyboard support**: Arrow-key panning, focusable viewport with visible focus ring, keyboard hint shown on focus.
- **Empty / first-run state**: Clear explanation + upload CTA — never a blank screen.
- **Blob URL lifecycle**: Systematic `URL.revokeObjectURL()` calls prevent memory leaks throughout the session.
- **Error messages**: Image validation errors (`ImageUpload.tsx:52`) and export errors are human-readable and actionable.
